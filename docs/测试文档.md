# 武侯祠游客服务中心 · 测试文档（问题与解决记录）

> 本文档汇总项目开发过程中的**测试验证过程**：把测试中暴露的**问题/需求**、**现象与根因**、**解决方式**、**验证结果**逐条登记，作为测试与调试的过程性材料。

---

## 一、测试方法与环境

| 维度 | 做法 |
|------|------|
| 后端单元测试 | JUnit5 + Mockito，`cd backend && export JAVA_HOME=D:/ETjdk17 && mvn test`（**40 个用例，全部通过**） |
| 接口测试 | 以真实角色登录取 Token，用 curl 调 `/api/**` 验证状态流转与权限（403/400） |
| 前端验证 | `npm run build` 通过（import 全解析）+ dev server 返回 200 + 页面操作核对 |
| 数据库验证 | MySQL 直接查表核对（行数/状态/字段），Navicat 可视化 |
| 环境 | JDK 17、MySQL 8.0.46、Node 22、Maven 3.9.9、高德 Web 服务 |

> 说明：环境无浏览器自动化工具，前端以「构建通过 + 接口实跑 + 页面逻辑核对」为准；真实视觉/交互由人工点击确认。

## 二、问题 / 需求登记与解决

### A. 环境与账号

| # | 问题/需求 | 现象与根因 | 解决 | 验证 |
|---|----------|-----------|------|------|
| A1 | 默认 JDK 为 25，构建报错 | Lombok 1.18.30 与 JDK 25 冲突：`ExceptionInInitializerError: TypeTag :: UNKNOWN` | 构建前设 `JAVA_HOME=D:/ETjdk17` | `mvn -version` 显示 Java 17 |
| A2 | 种子账号登录失败 | 源项目沿用的 bcrypt 哈希 `$2a$10$Eix…` **并不匹配 `123456`** | 用 spring-security-crypto 重新生成并校验过的哈希写入 `init.sql` | 各账号登录返回 200 |
| A3 | 后端服务易被回收 | 后台 `&` 启动的进程随工具会话结束被回收 | 改用 `nohup … & disown` 独立启动 | 端口长期监听 |
| A4 | 多窗口需登录不同角色且互不影响 | 需确认鉴权存储方式 | 鉴权用 **sessionStorage**（按标签页隔离），无 localStorage | 两窗口不同角色互不干扰 |

### C. 游客投诉

| # | 问题/需求 | 现象与根因 | 解决 | 验证 |
|---|----------|-----------|------|------|
| C1 | 审批点「通过」却弹「驳回」框、点驳回反而通过 | 弹框模板用 `action`，脚本变量是 `dialogAction`（模板取到 undefined） | 统一为 `dialogAction` | 通过/驳回弹框与动作一致 |
| C2 | 提交投诉需可上传图片/视频 | — | 提交弹窗加 `el-upload`（先建投诉，再按新 id 上传附件） | 附件出现在内容处 |
| C3 | 投诉附件应在「投诉内容」处缩略图（点击下载） | 原在独立「相关附件」区 | 详情内容下渲染缩略图网格（图片/视频可预览、点击下载） | 缩略图显示 |
| C4 | 回复记录与审批时间线合并 | 两处分离 | 合并为**「回复记录」**时间线，按时间呈 提交→审批→回复→处理→确认→结案→评分 | 顺序正确 |
| C5 | 游客追加回复改为弹窗 | 原为内联文本框 | 「回复」按钮 → 弹窗（文本 + 图片/视频上传） | 回复带附件 |
| C6 | 岗位列表用「详情」链接、进入无回复按钮 | 列表直接显示内容；职责需分离 | 4 个岗位列表内容列改「详情」→ `/complaints/:id`；详情页回复按钮**仅游客本人**可见 | 岗位只读 |
| C7 | 员工回复附件应在其回复位置，不混入投诉内容 | 原回复附件全挂到投诉 → 混入内容缩略图 | 引入 `related_type='COMPLAINT_REPLY'`，按回复 id 关联，呈现在该回复项内 | 归属正确 |
| C8 | 游客回复触发状态回退 | 驳回后无法再审批、处理完成后无法再处理 | 游客回复：`REJECTED→PENDING`（重回审批）、`RESOLVED→PROCESSING`（重回处理） | 对应列表重现该投诉 |
| C9 | 处理弹框附件同回复一致 | 原用通用上传组件 | 改为 `el-upload`；`process` 生成处理人回复承载附件 | 处理人回复带缩略图 |
| C10 | 处理后回复重复两条（文字+图片 / 文字） | `process` 生成一条 + 详情又按 `result` 合成一条 | 删除按 `result` 合成的记录，仅保留带附件那条 | 仅一条 |
| C11 | 列表编号与时间对应（越早越小） | 列表按时间倒序、编号用数据库 id | 后端改**按时间升序**，前端编号用**顺序号** | 顺序与时间一致 |
| C12 | 游客可删除自己的投诉（彻底） | — | `deleteComplaint`：先删回复 → 删审批流/节点 → 删审批记录 → **物理删除**投诉 | 删后 DB 各表 `0`，详情 404 |
| C13 | 删除后列表编号连续 | — | 编号用列表顺序号（非数据库 id） | 删除后自动顺延 |

## 三、酒店预订：需求细化结论（grilling 8 问）

| 项 | 结论 |
|----|------|
| 1 已预定口径 | **基准已预定 + 覆盖该日期的有效预订数**（当日计算，不落库） |
| 2 预订字段 | 游客/酒店/房型/单价快照/入住/离开/人数/**总价**/状态/时间 |
| 3 房态录入 | 新建**房型基准表** `room_type`（每酒店每房型一行：总量/基准已预定/价格） |
| 4 人数 | **不影响价格**，仅记录 |
| 5 下单校验 | 逐日校验余量 `rem(d)=总量−当日已预定`，任一天 <1 则拒绝 |
| 6 状态 | `BOOKED/CANCELLED`；游客可取消 |
| 7 日期/角色 | `离开≥入住`；**仅游客**可下单，其余只读 |
| 8 订单列表 | 仅本人、按创建时间倒序、含已取消（灰显不可再取消） |

**验证算例**（实测）：锦华酒店·商务大床房 单价 520、基准已预定 2 → 游客订 9/10–9/11、1 人 → **总价 1040**；下单后 9/10、9/11 已预定 **3**，9/12 回落 **2**；取消后回到 **2**。

## 五、结论

- 全过程共登记并解决 **30+ 项问题/需求**（环境 4、前端 7、投诉 13、应急 1、酒店 9、注册 4、外部服务 3）。

- 所有对外功能均以真实角色 + 接口实测通过；前端构建通过、页面可用。
